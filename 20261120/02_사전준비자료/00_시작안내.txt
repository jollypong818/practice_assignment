Day25 · 11월 20일 보고서 처리 Agent · 사전 제공 자료 v1.4

가장 먼저 00_사전준비_실행안내.html을 브라우저에서 여세요.

1. 이 묶음의 역할
   SQL, 초기 데이터, Postman 요청·환경, 환경설정 예시를 미리 제공합니다.
   SQL과 JSON 파일은 완성된 제공 자료이므로 TODO를 채울 필요가 없습니다.
   기존 Day25_실습자료_v1.4_필수보완.zip의 학생 프로젝트와 함께 사용합니다.

2. 수업 전에 준비할 것
   - 기존 수업용 Python 가상환경과 패키지 확인
   - pgAdmin에서 report_agent_lab DB 준비
   - 해당 DB의 preflight.sql → schema.sql → seed.sql → verify.sql 확인
   - E5 모델 캐시 준비(모델 차원 384 확인)
   - Postman Collection와 Environment JSON 두 파일 Import

3. DB 생성 위치를 구분하세요
   - 00_create_database.sql: 기본 postgres DB에서, 실습 DB가 없을 때만 1회
   - preflight.sql/schema.sql/seed.sql/verify.sql: report_agent_lab DB에서
   - 처음 시드만 넣은 상태: 분류 6 / 보고서 180 / 상세 각각 30 / Prompt 버전 60
   - 이때 벡터 0개, pending 180개가 정상입니다.
   - 이미 색인한 DB나 CRUD를 수행한 DB에는 최초 적재 숫자를 그대로 적용하지 않습니다.

4. 수업 중 직접 구현할 것
   Python의 CRUD·E5 어댑터·일괄 색인·검색·LLM·Agent는 학생 프로젝트에서 구현합니다.
   이 사전 제공 폴더에는 app/ 또는 완성된 Python 정답이 없습니다.
   따라서 이 폴더에서 python -m app.main 또는 index_overviews.py를 실행하지 않습니다.
   Postman도 사전에는 Import까지만 하고, 해당 기능을 구현한 뒤 요청을 실행합니다.

5. 프로젝트와 연결하는 방법
   학생 프로젝트를 받은 뒤 common/sql/, common/requirements.txt,
   common/.env.example, common/.gitignore를 선택한 프로젝트 루트로 복사합니다.
   기존 .env에 입력한 본인의 값을 덮어쓰지 않습니다. 처음이라면 .env.example을 .env로 복사합니다.
   기존 실습 common/data/search_cases.json은 이 묶음의 보완본을 사용합니다.
   Advanced의 evaluation_cases.json 복사 위치는 common/data/README_DATA.txt에 있습니다.
   common/README_START.md는 이후 전체 프로젝트 구현 안내입니다.

6. Postman 기본값
   Environment: Report Agent | Windows Local
   base_url: http://127.0.0.1:8000
   allow_paid_llm: false
   Basic에서는 02·03의 상위 단계 요청을 실행하지 않습니다.
   06 유료 요청은 필요한 것만 개별 실행하고, 07·08 생성 데이터 정리보다 먼저 확인합니다.

7. 교사용 확인
   DB 스키마·시드·Postman 요청 계약은 검수된 실습자료와 같습니다.
   읽기 전용 preflight SQL과 사전준비 안내를 추가했습니다.
   검색 확인표는 회의/프롬프트 주제의 연구계획, 가중치 주제의 업무보고서도
   관련 문서가 될 수 있음을 보완했습니다. 문서 유형과 검색 주제는 서로 다릅니다.
   실제 Windows PostgreSQL·pgvector·E5·LLM·Postman 연동은 강사 PC에서 확인합니다.
