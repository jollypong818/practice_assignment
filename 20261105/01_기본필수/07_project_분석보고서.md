## 1. 프로젝트 흐름과 목적

이 프로젝트는 이미지가 원(circle), 사각형(square), 삼각형(triangle) 중 무엇인지 분류하는 전이학습 실습이다. 별도의 합성 도형 이미지로 사전학습한 작은 CNN의 특징 추출부(Backbone)를 가져오고, 현재 데이터에 맞는 분류기(Head)만 학습하도록 설계되어 있다. 모델은 TinyShapeCNN 계열이며, ImageNet으로 사전학습한 ResNet18은 아니다.

### 데이터 준비

`ImageFolder`로 `data/train`과 `data/valid`를 읽는다. 클래스 번호는 폴더 이름의 정렬 순서에 따라 `circle=0`, `square=1`, `triangle=2`로 정해진다. 실제 파일 수는 다음과 같다.

| 분할 | circle | square | triangle | 합계 |
|---|---:|---:|---:|---:|
| 학습(train) | 12 | 6 | 3 | 21 |
| 검증(valid) | 3 | 3 | 3 | 9 |

입력 이미지는 32×32 크기로 조정하고, RGB 3채널의 0~1 범위 텐서로 변환한다. 전체 학습·검증 이미지를 각각 하나의 텐서로 쌓아 한 번에 처리한다. `test` 데이터는 실행 과정에서 읽거나 평가하지 않는다.

### 모델 구성과 전이학습 설정

모델은 두 개의 합성곱 층과 BatchNorm, ReLU, 풀링으로 특징을 추출한다. 16×4×4 특징을 256개 값으로 펼친 뒤, 마지막 `Linear(256, 3)`에서 세 클래스의 점수(logit)를 출력한다.

`data/source_backbone.npz`에서 Backbone 가중치를 불러오고 새 Head는 현재 실행에서 초기화한다. 제공된 `source_provenance.json`에 따르면 Backbone은 별도 source 학습 이미지 240장과 검증 이미지 60장으로 준비되었으며, 현재 target 데이터는 사전학습에 사용되지 않았다. 이 보고서에서 source 사전학습을 다시 실행한 것은 아니다.

Backbone의 가중치를 고정하고 Head의 가중치와 편향 771개만 학습 대상으로 지정한다. `model.eval()`로 BatchNorm의 저장 통계를 유지한다. `eval()` 자체가 기울기 계산을 막는 것은 아니므로, 이 설정에서도 Head 학습은 가능하다.

### 학습·평가·결과 저장

설계상 학습 순서는 다음과 같다.

1. 난수 시드 14를 고정한다.
2. AdamW(학습률 0.01, weight decay 0.0)와 교차엔트로피 손실을 설정한다.
3. 8 epoch 동안 학습하고 매 epoch 검증 손실을 측정한다.
4. 검증 손실이 가장 작은 시점의 모델 상태를 복원한다.
5. 검증 이미지별 예측과 정확도, Macro F1, 혼동행렬을 저장한다.
6. 실제 오답 이미지와 Grad-CAM을 생성하여 예측을 분석한다.

이번 작업에서 B07에 역전파와 가중치 갱신, B08에 최대 logit의 클래스 선택, B09에 UTF-8 JSON 저장을 구현했다. 각 코드에는 역할을 설명하는 주석을 추가했다. Backbone 고정, 입력 변환, 데이터 분할 등 나머지 실험 조건은 유지했다.

### 저장 결과와 시각화의 확인 범위

네 개의 CSV와 `metrics.json`이 생성되었다. 최종 오답은 0건이므로 `project_error_*.png`가 없는 것은 정상이다. 수정 전 오답 6건을 최종 모델의 오답으로 보고하지 않는다.

한편 `project_cam.png`는 이번 수정 후 실행에서도 출력 폴더에 생성되지 않았다. `cv2.imwrite()`의 성공 여부를 확인하지 않는 코드이므로 정상 종료만으로 저장 성공을 판단할 수 없다. Windows의 한글 경로 처리 문제는 가능한 원인 중 하나이며, 별도 확인이 필요하다. 실제 CAM 이미지를 열어 보지 못했으므로 모델이 도형 중심이나 배경에 주목했다는 시각적 결론은 내리지 않았다.

오답이 없을 때 CAM 코드는 검증 데이터 첫 이미지인 `circle_000.png`를 선택한다. 수정 후 이 이미지의 예측 클래스는 circle이므로 CAM 대상도 circle logit이다. Grad-CAM은 해당 점수와 관련된 영역을 보여주는 참고 자료이며, 정답이나 인과관계를 입증하는 자료는 아니다.

## 3. 한계점과 보완 방안

### 작은 데이터와 독립 평가의 부족

학습 이미지가 21장, 검증 이미지가 9장뿐이다. 검증 이미지 한 장의 정오 여부만 달라져도 정확도가 약 11.11%p 변한다. 따라서 이번 100%는 작은 검증 집합에서 모두 맞혔다는 의미로 해석해야 하며, 실제 사진이나 새로운 환경에서도 같은 성능을 낸다고 일반화할 수 없다.

또한 검증 데이터로 epoch를 선택하고 같은 데이터에서 성능을 보고했다. 이 값은 독립적인 최종 평가값이 아니다. 수업의 test 미사용 규칙을 유지하면서 개발하고, 최종 성능 검증은 허용된 별도 평가 절차 또는 새 독립 데이터로 진행해야 한다.

### 클래스 불균형과 합성 데이터의 한계

학습 데이터는 원·사각형·삼각형이 12:6:3으로 불균형하다. 이번 검증에서는 세 클래스 모두 맞혔지만, 클래스당 검증 이미지가 3장이므로 소수 클래스의 성능 문제가 없다고 단정할 수 없다. 데이터를 확대하고 클래스별 재현율·Macro F1을 함께 평가한다. 필요하면 학습에만 클래스 가중치 또는 샘플링을 적용한 후보를 만들고 동일한 검증 집합에서 비교한다. 이미 9장을 모두 맞힌 상태에서는 이 작은 집합의 정확도만으로 개선안을 구별하기 어렵다는 점도 고려해야 한다.

입력은 32×32의 단순 합성 도형이다. 새 데이터에서 배경·색상·위치·크기 조건별 성능을 확인하는 것이 필요하다. 학습 데이터에 증강을 적용할 수 있지만, 도형이 잘려 라벨의 의미가 달라지지 않도록 해야 한다. 검증 데이터에 무작위 증강이나 재추출을 적용해 결과를 유리하게 만들지 않는다.

### 전이학습 효과를 분리하는 비교 실험의 부족

이번 수정 전 실행은 학습과 예측이 미완성되어 있으므로, 사전학습의 효과를 검증하는 정상적인 대조 실험이 아니다. 동일한 입력·분할·학습 예산·평가 방식에서 사전학습 Backbone과 무작위 초기화 모델을 비교해야 source 가중치의 기여를 논의할 수 있다.

현재는 Backbone을 고정하고 Head만 학습했다. 데이터가 충분해지면 마지막 합성곱 층과 Head를 작은 학습률로 함께 조정하는 후보도 비교할 수 있다. 추가 학습이 반드시 개선을 보장하지는 않으며 작은 데이터에서는 과적합을 일으킬 수 있다. BatchNorm 통계의 고정 정책도 함께 기록해야 한다.

### 저장·재현·확장의 보완

| 남은 한계 | 보완 방법 |
|---|---|
| CAM 이미지 저장 결과를 확인하지 않음 | 저장 반환값과 파일 존재 확인. 필요하면 `cv2.imencode()`와 `tofile()` 등 Unicode 경로 대응 방식을 검증해 적용 |
| softmax 점수의 보정 성능 미확인 | 더 큰 독립 평가 데이터에서 신뢰도와 실제 정답률의 관계 확인 |
| 시드 하나의 결과만 확인 | 동일 설정 재실행 일치 여부 확인 후 여러 시드의 평균·변동 보고 |
| 입력·환경 기록이 코드와 분산됨 | 데이터 분할, 클래스 매핑, 변환, source 해시, 라이브러리 버전을 실험 기록으로 보존 |
| 전체 데이터를 한 번에 메모리에 적재 | 데이터가 커지면 DataLoader와 미니배치 도입 |
| 고정 Backbone 특징을 매 epoch 재계산 | Head 전용 학습에서는 특징을 사전 계산하는 방식 검토 |

B07의 `loss.backward()`·`optimizer.step()`, B08의 `logits.argmax(dim=1)`, B09의 UTF-8 JSON 저장은 이번에 구현하고 실행으로 확인했다. PyCharm의 오류 검사에서도 해당 파일의 오류는 0건이었다. 남은 우선 과제는 CAM 저장 확인과 더 다양한 독립 데이터에서의 평가이며, 이를 통해 이번 작은 검증 집합에서 관찰한 성공이 어느 범위까지 유지되는지 확인할 수 있다.
