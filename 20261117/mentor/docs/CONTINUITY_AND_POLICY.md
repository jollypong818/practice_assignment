# 교안과의 일치 · 실행 정책

기준: `Day22_Lecture_20261117.pptx`, 86장. PPT는 변경하지 않았습니다.

## 그대로 유지한 내용
지식 스냅샷101~103, H01~H03, Day21의 `KnowledgeAnswer`·엄격 JSON 파서·출처/상태 검증을 그대로 가져왔습니다. `coursekit/contracts.py`는 Day21 mentor 파일과 byte 단위로 동일합니다. H질문은 이미 사용한 연동·회귀 확인 사례이며 새 holdout 성능이 아닙니다.

공급자는 Responses API 한 경로를 사용합니다. `WireAnswer`는 전송 형식, 기존 `KnowledgeAnswer`는 로컬 규칙입니다. 출력의 안전 거절·불완전·실패는 정상 답변으로 바꾸지 않습니다. `insufficient_context`는 API 실행 실패가 아니라 유효한 업무 결과일 수 있습니다.

## 발췌를 실행 코드로 구체화한 부분
이 항목은 PPT 내용 변경이 아니라 실행 자료에서 정한 구체적인 선택입니다.

- 지시/질문·지식 분리: 전날 제공 기준 Prompt B의 고정 역할·근거 규칙·출력 계약을 `instructions_v1.txt`에 담고, 질문·선택 지식은 `input` JSON으로 옮겼습니다. 개인별 최종 선택 Prompt라고 주장하지 않습니다. `--prompt-file`로 본인이 고정한 지시 txt를 사용할 수 있으며 실제 문자열 해시가 버전으로 남습니다.
- API의 표준 text 단가를 명확히 적용하도록 `service_tier="default"`를 요청에 명시했습니다. Priority·Flex·Batch·지역 추가비용은 계산 범위 밖입니다.
- 본문36장과 부록75장의 대기 표현 중 **75장 방식**을 사용합니다. `max(서버 최소대기, 지수대기)+jitter` 후 남은 예산 이상이면 deferred로 중단합니다. 둘 다 서버 최소대기를 줄이지 않는 원칙입니다.
- 거절 콘텐츠의 이름은 `refusal`, 실행 결과 이름은 `refused`로 통일했습니다.
- 출력 JSON/Schema 오류만 최대1회 형식 수정 대상입니다. 통신은 생성당최대2회·작업전체최대4회입니다. 최초 호출과 수정 호출은 같은 예산을 공유합니다. 401·403·quota·알수없는429·timeout·스트림중단에는 자동 재전송하지 않습니다.
- 실제 호출은 명시적 `--allow-paid`, 개인20회 공유 장부로 제한합니다. 동시에 실행하지 않습니다.
- 캐시는 교육용 메모리 dict입니다. 별도 사람 검토 기록으로 승인한 원래 답변을 읽어 캐시에 적재하고, 같은 입력을 재조회합니다. Redis·공유 캐시·서비스 배포는 추가하지 않았습니다.

## 로그의 시간·사용량 해석
`attempts[*].request_ms`는 해당 전송 시작→종료입니다. 실행의 `request_ms`는 여러 전송의 request_ms 합이며 대기는 제외합니다. `first_text_ms`는 **첫 시도**의 첫 비어 있지 않은 delta 관측값입니다. 수정 시도의 첫 표시 시간은 그 attempt 안에 별도로 남습니다. `e2e_ms`는 입력 준비·대기·응답·검증까지이고 파일 저장/사람 평가 시간은 제외합니다. 동기 I/O timeout은 엄밀한 작업전체 deadline이 아닙니다. 스트림 이벤트 사이에서 협조적으로 종료를 확인합니다.

`usage` 최상위는 마지막 응답의 사용량입니다. **전체 사용량·비용을 마지막값 하나로 판단하지 말고 attempts 전체를 봅니다.** 누락된 실패 비용이 있으면 알려진 추정합과 전체추정(None)을 분리합니다. cached는input, reasoning은output의 일부입니다.

모의 사용량·가상시계는 `simulated`와 `example_estimated_usd`로 표시합니다. 실제 추정비용을 만들지 않습니다. 캐시 히트는 새 전송0·새 사용량0·새비용0이고 `origin_run_id` 및 원출처를 보존합니다.

스트리밍 콘솔에는 미검증 표시와 함께 delta를 즉시 출력합니다. `first_text_ms`는 클라이언트의 첫 텍스트 이벤트 관측값이며 브라우저 렌더링 완료 시간은 아닙니다.
각 전송의 `request_hash`와 `is_format_repair`로 원요청과 형식 수정 요청을 구분합니다.

`scope`는 캐시를 구분하기 위한 수업용 범위 식별자입니다. 실제 로그인·권한 검사를 구현한 것이 아니며, 운영 서비스에서는 검증된 사용자/테넌트 권한에서 범위를 계산해야 합니다. `store=False`도 모든 공급자 보관 정책이 자동으로 없어짐을 뜻하지 않습니다. 수업에는 제공된 가상 지식만 전송합니다.
