# 실습 07 · Indexing 상세 해설

**수준:** 03_advanced · **구분:** mentor

이 문서는 개념과 구현의 이유를 설명합니다. Python 파일과 함께 읽되 다른 강의자료에 의존하지 않아도 됩니다.

## 처리 흐름

검증된 Chunk → E5 Embedding → Stage → Transaction Publish → Top-k 검색

## 핵심 개념과 구현 시점

### 구현 단계 1
Indexing 입력은 검증된 Chunk의 내용과 출처입니다. 임의로 만든 384개 숫자를 E5 Embedding이라 부르지 않습니다.

### 구현 단계 2
E5 모델은 한 번 로드해서 CPU로 추론합니다. passage와 query의 접두어, 모델 ID, 정규화, 차원을 동일 계약으로 유지합니다.

### 구현 단계 3
Stage는 아직 조회에 노출되지 않은 새 버전을 DB에 저장하는 단계입니다. 같은 Chunk ID의 본문 불일치는 조용히 덮어쓰지 않습니다.

### 구현 단계 4
현재 `current_pointer()`는 SELECT로 공개 포인터만 읽습니다. Publish 자체는 실습 07의 A06에서 별도 Transaction으로 수행합니다.

Publish는 staging된 대상의 수와 상태를 검증하고 현재 포인터 쌍을 변경하는 짧은 Transaction으로 처리합니다.

### 구현 단계 5
의도적 오류는 학생 개인의 ingest_ 전용 Schema 안에서만 실행합니다. Rollback 이후 current pointer가 바뀌지 않은지 확인합니다.

### 구현 단계 6
v2 공개 후에는 이전 v1 청크가 현재 검색 결과에 섞이지 않아야 합니다. 반환된 원문·ID·버전을 확인합니다. 이 예제는 청크 수 감소를 검증하지 않습니다.

## 수강생이 자주 혼동하는 부분
- 단순 프로그램 실행 성공과 실제 DB·모델 실행을 구분합니다.
- 빈 결과/실패 사유를 임의로 정상 데이터로 바꾸지 않습니다.
- 코드 변경 전후에 같은 테스트와 원문 비교를 실행합니다.
