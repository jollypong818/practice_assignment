# 실습 01 · Collection 상세 해설

**수준:** 03_advanced · **구분:** mentor

이 문서는 개념과 구현의 이유를 설명합니다. Python 파일과 함께 읽되 다른 강의자료에 의존하지 않아도 됩니다.

## 처리 흐름

원본 파일 → bytes·Manifest → SHA-256·상태 → 변경 탐지

## 핵심 개념과 구현 시점

### 구현 단계 1
원본 수집 시 경로가 존재하는지 확인하고 read_bytes()를 사용합니다. text decode는 다음 실습에서 수행하므로 이 단계에서 원문 바이트를 바꾸지 않습니다.

### 구현 단계 2
len(raw)은 Byte 길이이며 len(text)와 같지 않습니다. SHA-256은 같은 바이트를 다시 확인하기 위한 식별 단서이지 문서의 내용이 진실임을 증명하지 않습니다.

### 구현 단계 3
문서 ID와 파일명은 다른 계약입니다. 원본 이름이 변경되어도 동일 문서의 이력을 doc_id로 이어갈 수 있어야 합니다.

### 구현 단계 4
지원 밖 확장자를 조용히 제외하면 입력 총수가 줄어듭니다. unsupported와 read_error는 별도의 상태로 남깁니다.

### 구현 단계 5
집계의 합이 원래 입력 수와 일치해야 수집 누락을 탐지할 수 있습니다. 실패도 분모에 포함시킵니다.

### 구현 단계 6
정해진 ID 순서와 JSON 직렬화 규칙으로 동일 파일의 fingerprint를 고정합니다. 재실행으로 값이 바뀌면 입력/설정이 달라졌는지 조사합니다.

## 수강생이 자주 혼동하는 부분
- 단순 프로그램 실행 성공과 실제 DB·모델 실행을 구분합니다.
- 빈 결과/실패 사유를 임의로 정상 데이터로 바꾸지 않습니다.
- 코드 변경 전후에 같은 테스트와 원문 비교를 실행합니다.
