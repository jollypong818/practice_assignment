# 실습 05 · Validation 상세 해설

**수준:** 03_advanced · **구분:** mentor

이 문서는 개념과 구현의 이유를 설명합니다. Python 파일과 함께 읽되 다른 강의자료에 의존하지 않아도 됩니다.

## 처리 흐름

Chunk 목록 → Schema·Span·중복·Coverage → 통과/Quarantine

## 핵심 개념과 구현 시점

### 구현 단계 1
Schema 검증은 필수 필드, 올바른 타입, 양의 위치 등을 확인하는 최소 Gate입니다. 누락을 정상 데이터로 바꾸지 않습니다.

### 구현 단계 2
clean_text[start:end]와 저장된 Chunk 본문이 완전히 일치하는지 확인해야 Citation이 다시 원문 구간을 가리킬 수 있습니다.

### 구현 단계 3
Overlap으로 일부 문자가 반복되는 것은 의도적일 수 있지만 동일 Chunk ID를 두 번 생성하는 것은 별도 오류입니다.

### 구현 단계 4
Coverage의 분모는 해당 clean_text 문자 수입니다. 중복 위치를 여러 번 더하지 않으며 원본 PDF 전체가 보존됐다는 뜻도 아닙니다.

### 구현 단계 5
격리한 입력은 사유·위치·ID를 남깁니다. 실패한 Chunk를 버리면 공개 전 검수에서 무엇이 누락됐는지 알 수 없습니다.

### 구현 단계 6
실패 사례 수정 후 정상 입력까지 다시 실행해야 합니다. 예외 검사를 강화하느라 정상 입력을 전부 차단하면 품질이 악화됩니다.

## 수강생이 자주 혼동하는 부분
- 단순 프로그램 실행 성공과 실제 DB·모델 실행을 구분합니다.
- 빈 결과/실패 사유를 임의로 정상 데이터로 바꾸지 않습니다.
- 코드 변경 전후에 같은 테스트와 원문 비교를 실행합니다.
