# 실습 01 · Collection Audit · 원문 버전·재수집

**난이도:** 03_advanced · **용도:** 수강생 TODO

## 목표
문서 식별·안전한 경로·파일 변경 탐지·오류 감사·재실행의 일관성을 관리합니다.

## 먼저 알아야 할 용어
- **Idempotent**: 같은 입력을 다시 처리해도 불필요하게 바뀌지 않음
- **Manifest**: 수집 대상을 빠짐없이 적은 목록
- **raw_sha256**: 원문 bytes에 대한 내용 해시
- **Audit**: 실패를 숨기지 않고 근거와 함께 기록

## 구현할 TODO

| ID | 요구사항 |
|---|---|
| `D24-01-A01` | 입력 manifest의 필수 필드·중복 ID·허용 형식과 경로 계약을 검증합니다. |
| `D24-01-A02` | 원문을 수집하여 bytes 길이·raw_sha256 또는 명시적 오류를 기록합니다. |

| `D24-01-A04` | 지원하지 않는 형식과 파일 접근 실패를 감사 목록에 기록합니다. |
| `D24-01-A05` | 입력 건수 = 수집·미지원·읽기 오류 건수인지 검사합니다. |
| `D24-01-A06` | 같은 파일·같은 순서 재실행 시 안정적인 manifest fingerprint를 계산합니다. |

## 실행 방법
- 수정 대상: `tasks.py`. `main.py`는 실행 진입점입니다.
- VS Code의 **Git Bash**에서 이 폴더로 이동하여 실행합니다. 기존 Python 가상환경을 사용합니다.
- `python main.py`

## 완료 기준
6건 상태 합과 안정 fingerprint, 변형 해시의 changed 판정. 실제 외부 문서 변경이 아님.

## 독립 실습과 결과
- 앞 교시가 미완성이어도 현재 폴더의 준비 코드와 `coursekit/` Checkpoint로 시작할 수 있습니다.
- 출력 파일은 해당 폴더의 `outputs/`에 생성됩니다. `data/raw/` 원문은 수정하지 않습니다.
- `expected/EXPECTED.md`는 평가 기준이지 실제 실행 로그가 아닙니다.
- 수강생은 실행 결과 외에 “어느 원문·어느 처리 버전·어느 실패 지점인가?”를 설명해야 합니다.
