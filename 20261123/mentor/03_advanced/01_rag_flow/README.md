# 실습 01 · RAG 단계와 근거 대조

**난이도:** 03_advanced · 심화  
**대상:** 강사 완성 코드  
**강의 연결:** 2026-11-23 HTML의 실습 안내 9페이지 / Chapter 1

## 목표

같은 문서를 사용하면서 질문 조건이 달라질 때 판단이 바뀌는 이유를 설명합니다.

## 먼저 알아야 할 용어

- **RAG**: 검색한 근거를 모델 입력에 넣어 답변을 생성하는 흐름입니다. 이 실습에서는 흐름과 근거를 먼저 정리합니다.
- **Context**: 이번 답변을 위해 선택한 참고 정보입니다. 원문 전체와 항상 같지는 않습니다.
- **Citation**: 답변이 가리키는 근거의 참조입니다. 문서 ID·버전·위치와 함께 대조합니다.
- **insufficient_context**: 현재 제공한 근거로 질문에 답할 수 없는 상태입니다. API 장애와는 다릅니다.

## 입력과 출력

- 입력: 오늘 제공한 data/lecture_hits.json의 강의 예시입니다. 출석 v2·과제 v1·시설 v1의 본문과 출처가 들어 있습니다.
- 수정할 파일: tasks.py. main.py는 tasks.py의 main을 실행합니다.
- 결과: 이 실습 폴더의 outputs/rag_flow.json. 파일 위치는 실행한 Terminal의 위치가 아니라 현재 실습 파일 경로를 기준으로 정합니다.
- 예시 데이터의 201·202·203은 설명용 ID입니다. 기본 실행 결과를 실제 DB 검색이나 LLM 생성 결과로 기록하지 않습니다.

## 구현할 부분

동일 ID가 수강생 코드의 TODO와 대응합니다. BEGIN/END 사이의 주석을 읽으며 왜 이 처리가 필요한지 설명하세요.

## 실행 방법

1. ZIP을 풀고 역할 폴더인 mentee 또는 mentor를 VS Code로 엽니다.
2. 기존에 사용하던 Python 가상환경이 선택되어 있는지 역할 루트의 안내로 확인합니다.
3. Git Bash Terminal에서 현재 실습 폴더(03_advanced/01_rag_flow)로 이동합니다.
4. 다음 명령으로 실행하고 검사합니다.

~~~bash
python main.py
python -m pytest -q tests
~~~

강사용은 모든 TODO가 완성되어 있습니다. 테스트는 현재 실습 함수의 결과를 검사하며 API·DB를 호출하지 않습니다.

## 완료 기준

- 15분은 지각, 20분은 결석, 사전 승인된 20분은 운영실 확인으로 구분합니다.
- 세 행의 원문·버전·출처가 모두 같습니다.
- 사전 승인을 자동 출석 인정으로 바꾸지 않습니다.

expected/EXPECTED.md와 outputs의 JSON을 비교한 뒤 reports/review.md의 질문에 답합니다. 자동 테스트는 자료형·연결·경계 조건을 확인하며 설명의 의미나 실제 답변의 Grounding을 대신 평가하지 않습니다.

## 문제가 생겼을 때

TODO가 남아 있으면 해당 ID의 NotImplementedError가 표시됩니다. 과제 문서가 없거나 요청한 문서 ID가 잘못된 경우에는 다른 문서를 대신 선택하지 않습니다.
