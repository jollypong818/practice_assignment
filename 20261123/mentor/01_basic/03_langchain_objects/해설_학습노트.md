# 실습 03 · LangChain 객체의 입력·출력과 invoke · 학습노트

**기본필수 / 강사용 코드 해설**

## 이번 단계가 필요한 이유

객체 이름만 외우지 말고 “무엇을 받아 무엇을 돌려주는가?”를 한 문장으로 설명합니다. 이 장에서는 Prompt 객체 생성과 invoke를 실제로 실행하지 않습니다. 실습 05에서 지금 정리한 입력·출력을 실제 객체로 확인합니다.

## 코드를 읽는 순서

### 1. component_outputs

네 구성요소의 반환값을 구분해 dict로 반환합니다.

설명할 점: Prompt는 ChatPromptValue, Chat Model은 AIMessage입니다. 입력이 실제로 어떤 값인지 먼저 출력해 보고, 함수의 반환값이 다음 단계에서 어디에 쓰이는지 연결해서 읽습니다.

### 2. access_kinds

Document는 data, 실행 구성요소는 invoke로 표시합니다.

설명할 점: 값 읽기와 실행을 구분합니다. 여기서는 실제 API 호출을 하지 않습니다. 입력이 실제로 어떤 값인지 먼저 출력해 보고, 함수의 반환값이 다음 단계에서 어디에 쓰이는지 연결해서 읽습니다.

## 결과를 해석하는 순서

1. outputs JSON의 execution을 읽고 구성요소의 역할을 정리한 로컬 확인임을 확인합니다.
2. components의 각 행에서 component·input·output·access를 나란히 읽습니다.
3. Prompt의 ChatPromptValue와 Chat Model의 AIMessage를 구분하고, Document는 값을 보관하는 data로 표시했는지 확인합니다.
4. reports/review.md에 각 구성요소가 무엇을 받아 무엇을 돌려주는지 자신의 말로 설명합니다.

## 확인 질문

1. 같은 invoke인데 Prompt와 Chat Model은 무엇이 다른가요?
2. Document에서 본문을 읽는 표현은 무엇인가요?
3. Document 목록을 question·context가 필요한 Prompt에 그대로 전달해도 되나요?

## 강사 설명 예시

**같은 invoke인데 Prompt와 Chat Model은 무엇이 다른가요?**

Prompt는 메시지를 구성하고 Chat Model은 모델에 답변을 요청합니다.

**Document에서 본문을 읽는 표현은 무엇인가요?**

doc.page_content입니다. metadata에서는 출처를 읽습니다.

**Document 목록을 question·context가 필요한 Prompt에 그대로 전달해도 되나요?**

이 예제의 입력 계약과 다릅니다. 선택한 문서를 문자열 Context로 만들고 질문과 함께 dict에 담아야 합니다.
