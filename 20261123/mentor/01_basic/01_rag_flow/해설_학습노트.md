# 실습 01 · RAG 단계와 근거 대조 · 학습노트

**기본필수 / 강사용 코드 해설**

## 이번 단계가 필요한 이유

이 실습은 사람이 강의 원문을 읽고 RAG 단계와 기대 판단을 기록합니다. 코드가 JSON을 저장해도 Retriever·Chat Model을 실제 실행한 것은 아닙니다. 출석 조건문은 가상 문서의 경계를 비교하는 수단이며 실제 기관의 정책 판정기로 사용하지 않습니다.

## 코드를 읽는 순서

### 1. stage_order

다섯 단계의 이름을 처리 순서대로 반환합니다.

설명할 점: 검색 → 근거 선택 → 메시지 작성 → 생성 → 확인 순서입니다. 입력이 실제로 어떤 값인지 먼저 출력해 보고, 함수의 반환값이 다음 단계에서 어디에 쓰이는지 연결해서 읽습니다.

### 2. evidence_note

입력 Hit의 출처·본문과 15분 질문의 판단·예외를 한 dict로 묶습니다.

설명할 점: source_locator와 body를 그대로 읽고, 문서의 “까지”와 사전 승인 조건을 확인하세요. 입력이 실제로 어떤 값인지 먼저 출력해 보고, 함수의 반환값이 다음 단계에서 어디에 쓰이는지 연결해서 읽습니다.

## 결과를 해석하는 순서

1. outputs JSON의 execution과 입력 출처를 먼저 읽습니다.
2. 원문 본문·ID·위치가 출력의 어느 필드에 남았는지 찾습니다.
3. expected의 조건과 대조하고, 다르면 처음 어긋난 함수의 입력·출력부터 확인합니다.
4. reports/review.md에 “어떤 값이 근거인가?”를 자신의 말로 기록합니다.

## 확인 질문

1. Context와 Prompt는 어떻게 다른가요?
2. 15분과 15분 초과가 다른 이유를 원문에서 찾으세요.
3. 이 JSON은 실제 LLM의 응답인가요?

## 강사 설명 예시

**Context와 Prompt는 어떻게 다른가요?**

Context는 선택한 참고 정보이고 Prompt는 규칙·질문·Context를 합친 모델 입력입니다.

**15분과 15분 초과가 다른 이유를 원문에서 찾으세요.**

“15분까지”와 “15분을 초과하면”이라는 서로 다른 조건이 있습니다.

**이 JSON은 실제 LLM의 응답인가요?**

아닙니다. 사람이 읽은 판단을 기록한 개념 확인표입니다.
