# 결과를 읽고 제출하는 방법

## 공통 제출

선택한 수준의 각 실습에서 **수정한 main.py/tasks.py**, 필요한 **outputs JSON**, **reports/review.md**를 준비합니다. `.env`, 가상환경, 캐시, API Key, DB 비밀번호는 포함하지 않습니다. 원문 data와 expected 파일을 답에 맞추어 변경하지 않습니다.

`expected/`의 JSON은 강사용 완성 코드를 실제로 **로컬/오프라인 실행한 관찰 예시**입니다. 모델 API의 실측 정답 파일이 아닙니다. 실제 LLM 답변 문장은 달라질 수 있으므로 EXPECTED.md의 조건과 원문을 함께 봅니다.

## 자동 통과와 사람이 확인할 부분

테스트는 자료형·호출 순서·경계 조건을 확인합니다. 자연어 설명의 이해도와 답변의 모든 주장이 원문에 의해 지지되는지는 테스트가 대신 채점하지 않습니다.

예를 들어 `source_ids=[201]`이 허용된 ID여도 “15분 늦으면 무조건 결석”이라는 주장은 출석 v2와 맞지 않습니다. **ID 유효성 검사 통과**와 **Grounding 확인**을 따로 기록합니다. 제출 기록지에는 원문 문장, 본인 판단, 그 이유를 짧게 적습니다.

실습 05·06의 `human_evidence_review=pending`은 아직 사람이 대조하지 않았다는 표시입니다. 실제 연동을 수행하지 못했다면 그 사실과 막힌 단계를 기록합니다. 오프라인 예시 관찰을 실제 API·DB 성공으로 바꾸어 적지 않습니다.
