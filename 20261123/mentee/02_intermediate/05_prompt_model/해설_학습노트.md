# 실습 05 · 해설과 학습 노트

**02_intermediate · 수강생용**

## 입력에서 응답까지

1. 질문 문자열과 Context 문자열을 Dictionary에 넣습니다. Key 이름은 Prompt의 변수 이름과 일치해야 합니다.
2. Prompt를 실행하면 규칙을 담은 system 메시지와 질문·자료를 담은 human 메시지가 만들어집니다. 이 과정은 로컬 문자열 구성입니다.
3. 완성된 메시지를 Chat Model에 전달할 때 실제 API 요청이 발생합니다. 모델 응답은 AIMessage입니다.
4. 요청 메시지와 응답 텍스트를 따로 기록합니다. 메시지 구성이 올바른지와 답변의 내용이 맞는지는 별도로 확인합니다.

## 먼저 구분할 세 가지

- **Prompt 입력 오류:** 필요한 Key가 없는 경우입니다. 모델이 답을 못한 상황이 아니라 모델 호출 전 코드 입력이 잘못된 상황입니다.
- **근거 부족:** 모델 요청은 가능하지만 제공 문서에 질문의 답이 없습니다. 과제 규정에 정확한 날짜가 없는 경우가 해당합니다.
- **호출 실패:** Timeout·인증 실패 등으로 요청을 완수하지 못한 상황입니다. 이를 문서 정보 부족이라는 답변으로 바꾸면 원인을 잃습니다.

## 원문 대조

출석 질문은 15분까지와 초과의 경계를 구분합니다. 사전 승인 예외가 있는지도 확인합니다. 과제 문서에는 개인 폴더라는 보관 장소는 있으나 정확한 제출 날짜가 없습니다. 모델의 자연스러운 설명을 그대로 승인하지 말고, 주장마다 원문이 실제로 지지하는지 확인합니다.

## 스스로 확인할 질문

1. 지금 확인한 값은 Prompt 입력, 완성된 메시지, 모델 응답 중 어디에 있는가?
2. API 요청이 시작되는 줄은 어디이며, 어떤 오류는 그보다 먼저 발생하는가?
3. 이 결과는 실제 모델 응답인가, 고정 예시인가? 기록에서 어떻게 구분하는가?
4. 타입·Key가 맞더라도 원문과 다를 수 있는 주장은 무엇인가?
