# 실습 01 · RAG 단계와 근거 대조 · 학습노트

**응용 / 수강생용 개념 설명**

## 이번 단계가 필요한 이유

이 실습은 사람이 강의 원문을 읽고 RAG 단계와 기대 판단을 기록합니다. 코드가 JSON을 저장해도 Retriever·Chat Model을 실제 실행한 것은 아닙니다. 출석 조건문은 가상 문서의 경계를 비교하는 수단이며 실제 기관의 정책 판정기로 사용하지 않습니다.

## 코드를 읽는 순서

### 1. stage_order

다섯 단계의 처리 순서를 반환합니다.

생각할 점: STAGE_CARDS의 이름을 사용합니다. 입력이 실제로 어떤 값인지 먼저 출력해 보고, 함수의 반환값이 다음 단계에서 어디에 쓰이는지 연결해서 읽습니다.

### 2. find_hit

목록에서 요청한 doc_id의 Hit를 반환하고 없으면 LookupError를 발생시킵니다.

생각할 점: 각 Hit의 doc_id를 순서대로 비교합니다. 입력이 실제로 어떤 값인지 먼저 출력해 보고, 함수의 반환값이 다음 단계에서 어디에 쓰이는지 연결해서 읽습니다.

### 3. deadline_note

문서 발견 여부와 정확한 날짜의 유무를 나누어 기대 판단을 작성합니다.

생각할 점: “담당자가 공지한 날짜”는 실제 날짜 값이 아닙니다. 입력이 실제로 어떤 값인지 먼저 출력해 보고, 함수의 반환값이 다음 단계에서 어디에 쓰이는지 연결해서 읽습니다.

## 결과를 해석하는 순서

1. outputs JSON의 execution과 입력 출처를 먼저 읽습니다.
2. 원문 본문·ID·위치가 출력의 어느 필드에 남았는지 찾습니다.
3. expected의 조건과 대조하고, 다르면 처음 어긋난 함수의 입력·출력부터 확인합니다.
4. reports/review.md에 “어떤 값이 근거인가?”를 자신의 말로 기록합니다.
